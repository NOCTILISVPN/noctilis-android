# Приложение NOCTILIS для Android — проект разработки

Заведено 22.09.2026 по решению Андрея: «нам надо сделать своё приложение хотя бы на Android для начала,
и чтобы весь проект разработки отображался на карте памяти, чтобы Влад тоже мог подхватывать».
Этот файл — живой план и журнал решений. Вкладка на карте: **«Приложение»** (app.automybiznes.com/memory/).

## Зачем своё приложение
Сейчас клиент ставит чужой Happ, вставляет ссылку подписки, разбирается в профилях. Половина
обращений в поддержку — «не подключается / что нажать». Своё приложение: поставил, открыл →
одна кнопка «Подключить» → работает. Ни бота, ни Telegram в цепочке нет. Внутри видно, сколько дней осталось, и кнопка «Продлить».
Бренд наш, никаких Provider ID и ограничений Happ Free.

## Что делаем (решения — мои, 22.09; помечено, где ждём Андрея)
| Вопрос | Решение | Почему |
|---|---|---|
| Ядро | **sing-box 1.14.1 + наш патч** (`core/patch-singbox.py`, библиотека libbox) | одно ядро умеет и VLESS Reality, и Hysteria2. 🔴 Без патча Reality на наших узлах не проходит: Xray на узлах с сентября 2026 требует в ClientHello пост-квантовую группу X25519MLKEM768, а sing-box её нарочно вырезает (issue #4520, открыт). Патч убирает фильтр **и** представляет клиента как Xray-core 26.7.11 в session id (новый Xray отбрасывает «старых» клиентов 1.8.x; так же сделал mihomo в PR #2983). При смене версии ядра — сверять `reality_client.go` |
| Язык | **Kotlin**, minSdk 26 (Android 8+) | родной для Android, VpnService штатно |
| Что в приложении, что на сервере | **тонкий клиент**: список серверов, правила маршрутизации (РФ мимо туннеля, MAX мимо) приходят с нашего сервера в формате sing-box | серверы и правила меняем без выпуска новой версии; правило живёт в коде на сервере, а не в приложении |
| Вход | **без Telegram**: приложение само заводит клиента при первом запуске (аккаунт привязан к устройству, восстановление — по коду/почте, решим на этапе 1) | Андрей 22.09: приложение делается, чтобы убрать зависимость от бота и Telegram, а не плодить её |
| Экраны (Андрей, 22.09) | **Один экран, 4 кнопки**: большая «Включить/Выключить» по центру; «Настройки»; «Исключения приложений»; «Оплата». Минималистичный дизайн. Первый запуск → аккаунт и пробный период сами | клиент не ходит ни в бот, ни на сайт |
| Главная фишка (Андрей, 22.09) | **Исключение приложений из VPN**: по умолчанию мимо туннеля MAX, Госуслуги, банки, навигация, VK, Rutube; список установленных приложений подтягивается с телефона сам, пользователь добавляет/снимает галочки | эти приложения ловят VPN или не работают через него |
| Маршрутизация | всегда «умная»: РФ-сайты и сети напрямую, остальное в туннель; сервер — автовыбор по пингу, в «Настройках» можно выбрать руками | правила приходят с сервера (`/app/config`) |
| Сборка | **GitHub Actions** → APK в Releases | на KZ 4 ГБ диска и 3 ГБ RAM — Android SDK/NDK не влезает |
| Подпись APK | ключ создан 22.09 workflow «Ключ подписи»: лежит в репозитории **зашифрованным** (`core/noctilis-keystore.p12.enc`), пароль — секрет GitHub `KEYSTORE_PASS`, его знает только Андрей (сохранён у него). Сборка расшифровывает и подписывает. | потеря пароля = нельзя обновить приложение у клиентов; первые сборки 0.0.2–0.0.16 были на случайных ключах раннера — ставились только с удалением |
| Раздача | страница **noctilis.net/app** (Андрей 22.09: «откуда скачивать — не знаю» → решил сам): открывается из РФ через Литву, APK лежит у нас (крон подтягивает свежий релиз с GitHub), GitHub Releases — зеркало; этап 2: Google Play ($25 разово) | по моим данным, Google в 2025–2026 снимал VPN-приложения из Play по требованиям РКН — Play не может быть единственным каналом |
| Репозиторий | **публичный** на GitHub | sing-box под GPLv3 → исходники приложения обязаны быть открыты; секретов в коде нет и не будет |
| Бренд | **NOCTILIS** (решение Андрея 22.09.2026) | персонаж и баннеры уже есть ([[noctilis-character-concept]]) |
| GitHub | **организация NOCTILIS под существующим аккаунтом Андрея** (новая почта не нужна), в ней репозиторий приложения; серверу — deploy-ключ с правом записи | персона Kelvin не светится: репозиторий принадлежит организации |

## Этапы
- **0. Подготовка** — репозиторий, ключ сервера, пустой проект Kotlin с CI: «зелёная сборка», APK-заглушка ставится на телефон.
- **1. MVP ✅ (22.09)** — регистрация без Telegram (аккаунт на устройстве → пробный период), туннель на sing-box, Подключить/Отключить, авто-выбор по пингу, дни до конца, оплата ЮKassa внутри приложения, промокод/рефералка. Серверная часть — новые ручки в xui-api / api.py NOCTILIS, формат подписки sing-box из `sub-hy2.py`.
- **2. Полировка** — MAX и банки мимо туннеля, автозапуск при старте телефона, уведомление за день до конца, обновление подписки по расписанию, обновление самого приложения (проверка версии с сервера).
- **3. Витрины** — Google Play; iOS (NetworkExtension, нужен Apple Developer $99/год) — отдельный проект.

## Как работаем вдвоём (Андрей + Влад, каждый своим Claude на KZ)
1. Рабочая копия одна — `/root/projects/techer-app/` на KZ, это же git-репозиторий (после этапа 0).
2. Перед правкой `git pull`, после — `git push`. Push запускает сборку, APK появляется в Releases.
3. Решения и статус — в этом файле (раздел «Журнал») и на вкладке «Приложение» карты. Задачи — в `memory/TASKS.md`.
4. Секреты (ключ подписи, токены GitHub) — только в `/etc/techer/` и хранилище, в репозиторий и заметки не класть.
